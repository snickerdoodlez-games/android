# Changes: June 8-9, 2026 — "WORD PAIRING" Header Update + verify_mode_names MCP Tool

## Summary
Replaced the display name "CLASSIC" with "WORD PAIRING" in the game header for standard classic levels, updated .clinerules documentation, created the `verify_mode_names` MCP tool in build-pipeline-mcp-server, and backed up to GitHub.

## Files Changed

### Modified: `components/Level1_Standard.tsx`
- **Line 239:** Changed `displayModeName` from `"CLASSIC"` to `"WORD PAIRING"`
- This applies to standard CLASSIC mode; SYNONYMS mode still shows `"SYNONYMS"`

### Modified: `components/Header.tsx`
- **Line 57:** Changed `MODE_NAME_COLORS` key from `'CLASSIC'` to `'WORD PAIRING'`
- Color remains `#00FFFF` (cyan)

### Modified: `.clinerules`
- Added new **Header Mode Names** section documenting all mode-name-to-color mappings
- Added note that `Level1_Standard.tsx` sets `displayModeName` to `"WORD PAIRING"` or `"SYNONYMS"`
- Added `verify_mode_names` to Build Pipeline MCP Tools list

### Modified: `build-pipeline-mcp-server/index.mjs`
- Added `VERIFY_MODE_NAMES_TOOL` definition with input schema
- Added `KNOWN_MODE_NAMES` constant mapping all 10 mode names to colors
- Added `handleVerifyModeNames()` async function that checks:
  1. Header.tsx MODE_NAME_COLORS for correct name→color entries
  2. Level1_Standard.tsx displayModeName for "WORD PAIRING" and "SYNONYMS"
  3. All level components for correct modeName passed to LevelLayout
  4. .clinerules documentation consistency
- Registered tool in `ListToolsRequestSchema`
- Added switch case in `CallToolRequestSchema`

## New Files Created
- `docs/changes_2026-06-08.md` — This changelog documenting all changes

- All changes compile successfully with `npm run dev` or `npm run build`
